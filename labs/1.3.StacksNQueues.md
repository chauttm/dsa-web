Dưới đây là 5 bài tập dạng **Bug Hunting (Sửa lỗi ngầm)** cho chủ đề **Stack (Ngăn xếp)** và **Queue (Hàng đợi)** bằng cả Java và Python.

Các đoạn mã này không có lỗi cú pháp, chạy đúng với các bộ dữ liệu cơ bản (Happy Cases), nhưng chứa lỗi ngầm về quản lý con trỏ, tràn bộ nhớ, hoặc vi phạm nguyên tắc cấu trúc dữ liệu khi gặp trường hợp biên.

---

## 1. Stack bằng Mảng (Java): Lỗi rò rỉ bộ nhớ (Memory Leak)

**Ngữ cảnh:** AI viết một Class triển khai Stack bằng mảng có khả năng tự động mở rộng kích thước (Dynamic Array Stack) trong Java. Mã nguồn chạy hoàn toàn đúng về mặt chức năng (Push/Pop đều chuẩn).

```java
public class MyStack {
    private Object[] elements;
    private int size = 0;
    private static final int DEFAULT_CAPACITY = 10;

    public MyStack() {
        elements = new Object[DEFAULT_CAPACITY];
    }

    public void push(Object e) {
        if (size == elements.length) {
            ensureCapacity();
        }
        elements[size++] = e;
    }

    public Object pop() {
        if (size == 0) {
            throw new java.util.EmptyStackException();
        }
        return elements[--size]; // Bug ngầm nằm ở đây!
    }

    private void ensureCapacity() {
        int newSize = elements.length * 2;
        elements = java.util.Arrays.copyOf(elements, newSize);
    }
}

```

### Nhiệm vụ của sinh viên:

1. **Tìm Bug:** Mã nguồn này chạy đúng, vậy tại sao nó lại bị coi là có lỗi "Rò rỉ bộ nhớ" (Memory Leak / Obsolete Object References)?
2. **Giải thích:** Cơ chế Garbage Collection (Bộ thu gom rác) của Java hoạt động dựa trên các tham chiếu. Dòng `return elements[--size]` đã bỏ quên điều gì khiến các đối tượng cũ bị Popped ra vẫn không bao giờ được giải phóng khỏi RAM?
3. **Sửa lỗi:** Sửa lại phương thức `pop()` để giải phóng tham chiếu cũ một cách an toàn.

## 2. Queue bằng Mảng vòng (Python): Lỗi đè dữ liệu khi đầy (Circular Queue Overflow)

**Ngữ cảnh:** AI được yêu cầu viết một Hàng đợi vòng (Circular Queue) bằng mảng kích thước cố định để tối ưu hóa việc tái sử dụng bộ nhớ.

```python
class CircularQueue:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.queue = [None] * capacity
        self.head = 0
        self.tail = 0

    public_is_empty(self) -> bool:
        return self.head == self.tail

    def enqueue(self, data) -> bool:
        # Kiểm tra xem hàng đợi có đầy không trước khi chèn
        if (self.tail + 1) % self.capacity == self.head: # Bug kiểm tra đầy!
            return False
        
        self.queue[self.tail] = data
        self.tail = (self.tail + 1) % self.capacity
        return True

    def dequeue(self):
        if self.head == self.tail:
            return None
        data = self.queue[self.head]
        self.head = (self.head + 1) % self.capacity
        return data

```

### Nhiệm vụ của sinh viên:

1. **Tạo Test case bẫy:** Khởi tạo `q = CircularQueue(3)`. Tiến hành `enqueue(1)`, `enqueue(2)`, `enqueue(3)`. Đoạn code trên có cho phép chèn phần tử thứ 3 không? Sức chứa thực tế của hàng đợi này là bao nhiêu?
2. **Giải thích bẫy logic:** Tại sao điều kiện `(self.tail + 1) % self.capacity == self.head` lại vô tình làm lãng phí mất 1 ô nhớ trong mảng, hoặc nếu sửa lại `self.tail == self.head` thì làm sao phân biệt được giữa lúc Queue "Rỗng" và Queue "Đầy"?
3. **Sửa lỗi:** Đề xuất một giải pháp (ví dụ: dùng thêm biến `size` hoặc mở rộng mảng thêm 1 phần tử đệm) để tận dụng tối đa đúng `capacity` được truyền vào.

## 3. Queue bằng 2 Stacks (Java): Lỗi hiệu năng $O(n^2)$ ẩn mình

**Ngữ cảnh:** Một bài toán kinh điển: Thiết kế một Hàng đợi (Queue) bằng cách sử dụng 2 Ngăn xếp (Stack). AI trả về đoạn code Java chạy đúng kết quả First-In-First-Out dưới đây:

```java
import java.util.Stack;

public class MyQueue {
    private Stack<Integer> stack1 = new Stack<>();
    private Stack<Integer> stack2 = new Stack<>();

    // Thêm phần tử vào cuối hàng đợi
    public void enqueue(int x) {
        stack1.push(x);
    }

    // Lấy phần tử ở đầu hàng đợi
    public Integer dequeue() {
        if (stack1.isEmpty() && stack2.isEmpty()) return null;
        
        // Chuyển toàn bộ từ stack1 sang stack2 để lấy phần tử đáy
        while (!stack1.isEmpty()) {
            stack2.push(stack1.pop());
        }
        
        int res = stack2.pop();
        
        // Chuyển ngược lại về stack1 để chuẩn bị cho lần enqueue tiếp theo
        while (!stack2.isEmpty()) {
            stack1.push(stack2.pop());
        } // Bug hiệu năng nằm ở đây!
        
        return res;
    }
}

```

### Nhiệm vụ của sinh viên:

1. **Phân tích hiệu năng:** Nếu ta thực hiện liên tiếp chuỗi thao tác: `enqueue`, `dequeue`, `enqueue`, `dequeue`... $n$ lần, độ phức tạp thời gian (Time Complexity) của mỗi thao tác `dequeue()` lúc này là bao nhiêu?
2. **Giải thích:** Tại sao vòng lặp `while` thứ hai (chuyển ngược dữ liệu về `stack1`) lại hoàn toàn dư thừa và phá nát hiệu năng khấu hao (Amortized Complexity $O(1)$) của thuật toán này?
3. **Sửa lỗi:** Hãy tối ưu lại phương thức `dequeue()` sao cho dữ liệu chỉ cần chuyển sang `stack2` khi thật sự cần thiết và giữ nguyên ở đó, giúp đạt tốc độ $O(1)$ khấu hao.

## 4. Stack bằng Danh sách liên kết (Python): Lỗi đảo ngược thứ tự (FIFO nhầm thành LIFO)

**Ngữ cảnh:** Sinh viên nhờ AI chuyển đổi Stack từ dạng mảng sang dạng Danh sách liên kết đơn (Linked List) để không lo giới hạn kích thước. AI trả về đoạn mã sau:

```java
class Node {
    int data;
    Node next;

    Node(int data) {
        this.data = data;
        this.next = null;
    }
}
    
public class LinkedStackBuggy {
    private Node head = null;
    private Node tail = null; // AI cố tình dùng thêm tail để "tối ưu" chèn cuối?

    public void push(int data) {
        Node newNode = new Node(data);
        if (head == null) {
            head = newNode;
            tail = newNode;
        } else {
            tail.next = newNode;
            tail = newNode; // Bug logic chèn đuôi nằm ở đây!
        }
    }

    public Integer pop() {
        if (head == null) {
            return null;
        }

        // Lấy dữ liệu ở head ra
        int res = head.data;
        head = head.next;
        
        if (head == null) {
            tail = null;
        }
        return res;
    }

    public static void main(String[] args) {
        LinkedStackBuggy stack = new LinkedStackBuggy();

        System.out.println("--- Thực hiện Push vào Stack: 1, 2, 3 ---");
        stack.push(1);
        stack.push(2);
        stack.push(3);

        System.out.println("--- Thực hiện Pop dữ liệu ra ---");
        // Theo nguyên lý Stack (LIFO): Phải ra 3 -> 2 -> 1
        // Nhưng đoạn code lỗi này sẽ ra kết quả của Queue (FIFO)
        System.out.println("Pop lần 1: " + stack.pop()); // Kết quả: 1
        System.out.println("Pop lần 2: " + stack.pop()); // Kết quả: 2
        System.out.println("Pop lần 3: " + stack.pop()); // Kết quả: 3
    }
}

```

### Nhiệm vụ của sinh viên:

1. **Tìm Bug:** Thực hiện chuỗi lệnh: `push(1)`, `push(2)`, `push(3)`, sau đó gọi `pop()`. Kết quả trả về là gì? Nó có tuân thủ nguyên lý LIFO (Last-In-First-Out) của Stack không?
2. **Giải thích:** Đoạn mã trên của AI thực chất đã biến cấu trúc dữ liệu này thành loại cấu trúc dữ liệu nào? Lỗi chèn nút mới vào `tail` thay vì `head` đã làm sai lệch cơ chế hoạt động của Stack ra sao?
3. **Sửa lỗi:** Viết lại phương thức `push` để chèn nút vào đầu danh sách (đầu `head`) nhằm đảm bảo đúng tính chất của Stack.

## 5. Thiết kế Min-Stack (Java): Lỗi sập bộ nhớ khi gặp giá trị trùng lặp

**Ngữ cảnh:** Bài toán yêu cầu thiết kế một Stack mà ngoài `push`, `pop`, nó còn có hàm `getMin()` lấy ra giá trị nhỏ nhất hiện tại trong Stack với độ phức tạp $O(1)$. AI sử dụng giải pháp 2 Stack song song (một Stack chứa dữ liệu, một Stack chứa giá trị Min nhỏ nhất tại thời điểm đó).

```java
import java.util.Stack;

public class MinStack {
    private Stack<Integer> stack = new Stack<>();
    private Stack<Integer> minStack = new Stack<>();

    public void push(int val) {
        stack.push(val);
        // Nếu là phần tử đầu tiên hoặc nhỏ hơn đỉnh của minStack thì thêm vào minStack
        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }

    public void pop() {
        if (stack.isEmpty()) return;
        
        int poppedValue = stack.pop();
        // Nếu giá trị rút ra bằng với giá trị nhỏ nhất hiện tại, loại bỏ nó khỏi minStack
        if (poppedValue == minStack.peek()) { // Bug so sánh Object ngầm định trong Java!
            minStack.pop();
        }
    }

    public int getMin() {
        return minStack.peek();
    }
}

```

### Nhiệm vụ của sinh viên:

1. **Tạo Test case bẫy (Bug Hunting):** Hãy chạy thử đoạn code trên với chuỗi thao tác sau: `push(512)`, `push(512)`, `pop()`, rồi gọi `getMin()`. Điều bất ngờ gì xảy ra với kết quả của `getMin()`? (Tại sao `512` lại không khớp nhau?)
2. **Giải thích bẫy Java:** Class `java.util.Stack` lưu trữ kiểu `Integer` (Object chứ không phải kiểu nguyên nguyên thủy `int`). Khi gọi `poppedValue == minStack.peek()`, Java đang so sánh cái gì? Tại sao các số nhỏ (như `10` hay `100`) thì code chạy đúng, nhưng số lớn (như `512`) thì code lại chạy sai? *(Gợi ý kiến thức: Integer Cache từ -128 đến 127 của Java)*.
3. **Sửa lỗi:** Thay đổi toán tử so sánh hoặc sử dụng phương thức phù hợp của Object trong Java để sửa triệt để bug này.

Chuỗi bài tập này đánh thẳng vào tư duy lập trình nâng cao. Sinh viên không thể chỉ dùng AI sinh code là xong, vì chính AI là "thủ phạm" tạo ra các đoạn mã bẫy này. Sinh viên bắt buộc phải nắm rất vững:

* Cách hoạt động của bộ nhớ máy tính (Heap/Stack).
